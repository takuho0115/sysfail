# L020 Every page returns "Forbidden"

1. On web01 (ops; use sudo for administrative operations), read the nginx error log
   - Use `sudo tail -n 5 /var/log/nginx/error.log` to look for the reason behind the 403 responses

2. Find the document root in the configuration
   - Also use `sudo nginx -t` to check that the configuration is valid

3. Inspect permissions along the entire path to the published file
   - `namei -l /usr/share/nginx/html/index.html`
   - Can the user running the nginx workers traverse each directory (x) and read the file (r)?

4. After correcting permissions, check that both the page and its css load

## Why investigate this area?

If the process is running and every page returns 403, nginx is receiving the requests and refusing them.
The recent permission changes are a clue. Workers run as a user other than root, so check whether that user can reach the files.

## Common pitfalls

- Checking only the final file and missing a directory along the path that lacks x permission
- Assuming there is no problem because sudo can read the file. The worker's user needs to read it
- Taking a shortcut by setting permissions to 777 (the completion conditions prohibit this)
