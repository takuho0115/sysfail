# L068 Small pages load, but large file downloads stall

1. On client01 (ops; use sudo for administrative operations), compare symptoms by response size
   - Run `curl -s -m 5 -o /dev/null -w '%{http_code} %{size_download}\n' http://web01/index.html` and retrieve large.bin in the same way
   - Check whether small pages succeed while only large files stall partway through

2. Check the MTU on each segment of the path
   - Run `ip -o link show` on client01, gw01, and web01 (all as ops), and record the mtu for each interface
   - Remember that gw01 has two interfaces: one internal and one external

3. Measure the packet sizes that can traverse the path
   - From web01 (ops) toward client01, vary the size with `ping -M do -s <サイズ> -c 2 -W 2`
   - Find the boundary between sizes that pass and those that fail, and check for notifications such as "Frag needed"

4. Check where large packets disappear
   - On gw01 (ops), capture with `sudo tcpdump -i any -n tcp port 80` while retrieving large.bin from client01
   - Check whether packets arriving on the internal side leave through the external side

5. After taking action, retrieve both large.bin and index.html again from client01

## Why investigate this area?

If connections establish and small responses arrive but large responses stall, investigate packet size rather than basic connectivity.
When a path contains a segment with a smaller MTU and the sender is not informed, only the large packets are silently dropped.
That explains the absence of an error. Finding the size boundary with ping helps clarify the cause.

## Common pitfalls

- Testing only with small pings or small pages and concluding that the path is healthy
- Changing the gateway's external MTU to make the values agree. This misrepresents the path's actual MTU and is prohibited by the completion conditions
- tracepath and `ip route get` may be unavailable in this environment. Measure using ping with different sizes
- Network changes are limited to the syntax allowed in this environment. `nft` accepts a narrow range of syntax, so a rejection does not necessarily indicate a permission problem. Check the permitted operations for `ip`, `iptables`, and `sysctl` too
