# L010 The app will not start

1. On web01 (ops; use sudo for administrative operations), find out why the application unit cannot start
   - `systemctl status shopapp`
   - Use `journalctl -u shopapp --no-pager | tail` to see what it says is missing

2. Trace where the unit reads its configuration
   - Use `systemctl cat shopapp` to locate the environment file it loads

3. Compare that file's contents with the surrounding files
   - Check file sizes with `ls -la /etc/shopapp/`
   - If there is an example file (.example), check its list of required variables
   - Look in the same directory for files that provide clues to the values

4. Set the required variables, restart, and verify
   - On toolbox (player), run `curl -i http://web01/` and `curl -i http://web01/status`

## Why investigate this area?

A 502 indicates that the application is not responding. If the unit failed to start, the quickest next step is to read the logs for the reason.
The claim that the configuration "should have been brought over from the previous environment" suggests that its contents may not have been copied.
A file's existence does not mean its contents are correct, so check its size and contents too.

## Common pitfalls

- Checking only that the file exists and missing that it is empty
- Adding only the variable named in the error and forgetting other required variables in the example
- Inventing values instead of taking them from the files that provide clues
- Forgetting to restart after configuring the application
