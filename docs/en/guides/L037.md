# L037 HTTPS connections fail only from older devices

1. On toolbox (player), compare connections from an older client and a modern browser
   - Check available profiles with `sfclient --help`
   - Compare the results and error messages from `sfclient --profile legacy --insecure https://web01/` and `--profile modern`

2. On web01 (ops; use sudo for administrative operations), read the nginx TLS configuration
   - Check ssl_protocols and ssl_ciphers in /etc/nginx/conf.d/tls.conf

3. On web01 (ops), try connecting with a cipher suite used by the older client
   - `openssl s_client -connect localhost:443 -tls1_2 -cipher <暗号スイート名> </dev/null`
   - Distinguish a protocol failure from a cipher-suite failure

4. After correcting the configuration, run `sudo nginx -t`, reload, and test both legacy and modern on toolbox

## Why investigate this area?

If a modern browser connects but an older client fails, the server is running but the client and server cannot agree on TLS parameters.
A handshake can fail when there is no common protocol version or cipher suite. Compare what the server permits with what the older client supports.

## Common pitfalls

- Enabling TLS 1.0 or 1.1 for the older client (the completion conditions prohibit this)
- Adding a similarly named cipher suite with a different key-exchange method and assuming it works. Test with the actual legacy profile
- Adding many cipher suites and reducing security more than necessary
