# L004 HTTPS shows a "connection is not secure" warning

1. On toolbox (ops), check the error message from the HTTPS connection
   - Read what kind of error it reports

2. On web01 (root), locate the certificate file
   - Check the certificate path in the nginx configuration

3. Inspect the certificate information
   - Does the file exist?
   - What is its validity period?

4. Compare the current time with the certificate's validity period
   - Is the current time inside or outside that period?

5. If it is outside the validity period, prepare a new certificate
   - Check which tools and methods are available in this environment

6. Check the configuration before reloading the service
   - Make sure the configuration is valid
   - Check that the service is using the new certificate

## Why investigate this area?

HTTPS connections can fail for several reasons.
Use the client-side error message to narrow down the cause, then check the server-side state.

## Common pitfalls

- Taking action without reading the error message
- Forgetting to reload the service after changing its configuration
- Missing a mismatch between the certificate's location and the path in the configuration
