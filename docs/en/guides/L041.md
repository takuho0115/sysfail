# L041 Order requests are piling up

1. On gw01 (ops; use sudo for administrative operations), inspect the buildup of connections
   - Use `ss -s` or `sudo ss -tnp` to see how many established connections there are and where they go
   - Use `curl -s -m 3 -w '%{http_code}\n' http://gw01:8080/order` to check whether the request waits or fails

2. Read the logs on each service
   - Run `journalctl -u mesh-svc --no-pager | tail -n 20` on gw01, svc-a, svc-b, and svc-c (all as ops)
   - Watch for the same request ID (req=...) appearing repeatedly

3. Make a table of the direction of each service call
   - Collect upstream values from /etc/mesh/svc.conf on each server with `grep -H '^upstream' /etc/mesh/svc.conf`
   - Write each "from → to" pair on a separate line, then follow the path from gw01 to see whether it reaches an endpoint

4. After correcting the configuration responsible, release the accumulated connections
   - Restoring the configuration alone will not free workers that are already stuck. Restart each service
   - On svc-a (ops), use `ss -tn state established | wc -l` to confirm that the connection count has fallen

## Why investigate this area?

If every service is slow and connection counts stay high on all hosts, investigate how the services are connected rather than focusing on a single unhealthy host.
The same request appearing repeatedly in the logs indicates that it keeps circulating between services without finishing.
Putting the configuration in a table and following the call directions reveals where the flow loops back.

## Common pitfalls

- Restarting only the service that looks slowest and waiting. If the cause remains, it will fill up again
- Trying to connect all the configurations in your head and reversing a call direction. Write a table on paper or in notes
- Waiting after correcting the configuration without restarting, leaving blocked workers in place
- To access another service host, use ssh from toolbox (the left pane), rather than from inside gw01. Hosts do not contain keys for accessing the other hosts
