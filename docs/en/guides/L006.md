# L006 The product list shows a "database error"

1. On web01 (ops; use sudo for administrative operations), check the application status and logs
   - Check its status with `systemctl status shopapp`
   - Use `journalctl -u shopapp --no-pager | tail` to read the type of error reported when connecting to the DB

2. Trace where the application reads its DB connection details
   - Use `systemctl cat shopapp` to locate the environment file loaded by the unit
   - Check the destination, username, and password in the configuration under /etc/shopapp/

3. Try connecting to the DB manually using the configured values
   - On web01 (ops), run `mysql -h db01 -u shop -p` and check whether it produces the same error as the application

4. Find where the correct values are documented
   - Read the operations handover notes (README) in the application directory

5. Correct the configuration, restart the application, and verify it
   - On web01 (ops), run `curl -fs localhost:8080/health`

## Why investigate this area?

If the home page opens but the product list fails, the application is running and the failure occurs in its interaction with the DB.
The report of recent work on the DB also suggests a mismatch between something changed on the DB side and the values the application still uses.
Whether the log reports a connection failure or an authentication rejection determines whether to investigate the network or the credentials.

## Common pitfalls

- Suspecting the DB server or network without reading the type of error
- Forgetting to restart the application after correcting the configuration, leaving it running with the old values
- Guessing new values before testing a manual connection
