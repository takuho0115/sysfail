# L011 The shop keeps going down and coming back within a minute

1. On web01 (ops; use sudo for administrative operations), confirm that the service is restarting repeatedly
   - Use `systemctl status nginx` to check how long it has been running since startup

2. Look in the logs for what is restarting the service
   - Use `journalctl --no-pager | tail -n 30` to read the records immediately before each restart
   - Look for a pattern: how many failures trigger a restart, and at what interval?

3. Find the configuration of the mechanism responsible for the restarts
   - Use its name from the logs as a clue to locate configuration files, for example with `sudo grep -ril <語> /etc`
   - Read what it checks and which command it uses

4. Run that check command manually under the same conditions
   - See whether it succeeds, and read its exit code if it fails
   - Use `sudo ss -ltnp` to compare the check's destination with the actual listeners

5. Once the check's destination matches the actual service, observe it for at least one minute to confirm that the restarts have stopped

## Why investigate this area?

When a service repeatedly stops and returns, an external monitor may be restarting it after judging it unhealthy, rather than the service crashing on its own.
If direct access works normally but it still gets restarted, the monitor's assessment may be wrong.
Reading what the monitor checks and repeating that check manually makes the mismatch clear.

## Common pitfalls

- Trying to adjust the service's startup logic or startup delay when the service itself works normally
- Spending too long searching for the monitor configuration. Search with grep using names and terms from the logs
- Creating configuration outside the game, on your own terminal. Perform the operations inside web01
- Finishing immediately after the correction. Observe across the restart cycle
