# L002 Connections to the shop time out from outside

1. On web01 (ops; use sudo for administrative operations), check whether the service itself is running
   - Use `ss -ltn` to check for listeners on ports 80 and 443
   - Use `curl -I http://localhost/` and `curl -k -I https://localhost/` to see whether it responds from inside the server

2. Try accessing it from toolbox (player) and observe how the request fails
   - Does `curl -I http://web01/` immediately report "connection refused", or does it wait and time out?

3. Investigate the controls in front of the server
   - On toolbox (player), run `cloud sg describe-security-groups` and find the security groups associated with web01
   - Read the inbound rules with `cloud sg describe-security-groups --group-ids <名前>` and make a table of the permitted ports and source ranges

4. Add any missing permission, limited to the scope needed
   - Find the available operations with `cloud sg help`, then check the syntax with `cloud sg <操作> help`
   - Use the source ranges in the existing rules as a reference when choosing the source

5. Test access from toolbox (player) again

## Why investigate this area?

If the page works inside the server but cannot be reached from outside, the problem lies on the path to the server rather than in the service.
A timeout is typical of traffic being silently dropped along the way.
Distinguishing a refused connection (no listener at the destination) from a timeout (traffic blocked before arrival) helps narrow the search.

## Common pitfalls

- Focusing only on nginx configuration inside the server when access from inside already works
- Opening a rule to all sources (0.0.0.0/0) when adding permission. Match the scope of the existing rules
- Broadening or deleting the existing SSH rules
