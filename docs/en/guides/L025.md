# L025 The site returns 503 errors

1. On toolbox (player), inspect the load balancer's status
   - `cloudctl lb describe-target-health --target-group-name web-lb`
   - Read each target's status and REASON, and the path used for health checks

2. On web01 (ops; use sudo for administrative operations) and web02 (ops), check whether that path actually responds
   - `curl -si http://localhost/<ヘルスチェックのパス> | head -1`

3. Find the path the web servers provide for health checks
   - Look for the health-check location in the configuration under /etc/nginx/

4. Decide whether to align the LB or the web servers, make the correction, and use `cloudctl lb describe-target-health --target-group-name web-lb` to confirm that all targets become healthy
   - `cloudctl lb help` lists available operations; check their syntax with `cloudctl lb <操作> help`

## Why investigate this area?

If the services on each server are running but everyone gets 503, the load balancer probably has no targets it considers available.
The LB chooses targets based on its own health checks, so first inspect each server's status from the LB's perspective and the request used to make that assessment.

## Common pitfalls

- Concluding that the servers are healthy just because nginx is running, without considering the LB's assessment
- Testing only the home page (/) instead of the health-check path
- If changing the web servers, remember to make the same correction on both
