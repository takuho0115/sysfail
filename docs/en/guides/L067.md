# L067 A process crashes at random

1. On img01 (ops; use sudo for administrative operations), examine how the service crashes
   - Use `systemctl status imgsvc` and `journalctl -u imgsvc --no-pager` to read the reason for termination (status= or signal name) and the interval between crashes
   - Distinguish an intentional exit from termination by a signal

2. Gather the crash records
   - Use `ls /var/lib/sfcore` to find the simulated core files left after each crash
   - Read backtraces from several cores side by side

3. Separate locations that vary between crashes from those that appear every time
   - Focus on functions appearing in every core, rather than just the function where a crash occurred

4. Find configuration related to that common element
   - Inspect service configuration such as /etc/imgsvc/env for settings connected to the common element
   - After changing it, restart and check that it stays running for a while (the completion conditions require at least one minute of continuous operation)

## Why investigate this area?

Crashes at different locations often mean that memory was corrupted earlier and different operations encounter it later.
A single backtrace can lead you to blame whichever operation happened to be there at the time.
Comparing several backtraces and finding the code they all pass through brings you closer to the cause.

## Common pitfalls

- Reading only the latest core and trying to fix the function shown there
- Missing crashes because the service recovers automatically and appears to be running. Check the restart records in the logs
- Judging immediately after changing the configuration. Crashes occur every few dozen seconds, so observe for a few minutes
