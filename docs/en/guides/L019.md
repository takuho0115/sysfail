# L019 The page loads but the product list stays empty (browser error)

1. On toolbox (player), reproduce the page's behavior
   - Read the error message from `browser-sim http://shop.acme.internal/`

2. On toolbox (player), use curl to send a request under the same conditions as the browser
   - `curl -si -H 'Origin: http://shop.acme.internal' http://api.acme.internal:8080/products`
   - Inspect the response headers rather than the body. Are the headers granting permission present?
   - Also check the response to an OPTIONS request (preflight)

3. On api01 (ops; use sudo for administrative operations), read the nginx configuration
   - Does the API configuration under /etc/nginx/conf.d/ specify the allowed origin?

4. After correcting the configuration, validate it with `sudo nginx -t`, reload it, and test `browser-sim` again on toolbox

## Why investigate this area?

If curl gets a 200 but only the browser fails, the API itself is running and the browser is discarding the response.
For a cross-origin request, the browser checks whether the server returns headers granting permission. That is why you should include Origin and inspect the headers rather than the body.

## Common pitfalls

- Ending the investigation because curl succeeds and assuming the API needs no further attention
- Using curl without Origin and failing to reproduce the browser's conditions
- Fixing only GET and forgetting the OPTIONS preflight
- Allowing all origins with `*` (the completion conditions prohibit this)
- Immediately after a reload, old workers may still respond with the previous configuration. Wait briefly and test again
