# L016 Placing an order never gets a response

1. Establish the scope of the symptoms
   - Browsing works, but order confirmation does not return. DB CPU usage is low

2. On db01 (ops; use sudo for administrative operations), inspect the DB sessions
   - Use `sudo mysql -e 'SHOW FULL PROCESSLIST'` to list what is running and what is waiting

3. Distinguish the blocked sessions from the sessions blocking them
   - Read the `State` of the waiting sessions to find out what they are waiting for
   - Look for long-running sessions (high `Time`) using the same table

4. Identify the purpose of the blocking query
   - Use the username and query contents to decide whether it is safe to stop

5. Terminate only the session you have decided to stop, then check order confirmation
   - Leave the order data itself untouched

## Why investigate this area?

If requests do not return while CPU usage is low, the work is waiting for something rather than consuming processing power.
In a DB, a session that keeps a table locked can force later operations to wait for that lock.
Comparing session states and running times helps reveal which session is blocking which.

## Common pitfalls

- Stopping the blocked order-processing session instead of finding the session blocking it
- Terminating every long-running query without first checking what each one is for
- Deleting order data or recreating tables as a shortcut
