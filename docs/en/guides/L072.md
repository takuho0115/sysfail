# L072 Uploads report success, but the files never appear

1. On web01 (ops; use sudo for administrative operations), check that the application is actually running
   - Confirm its running status with `systemctl status uploadapp`
   - Since it reports success but the file is missing, investigate the save operation rather than components outside the application

2. On web01 (ops), identify the user running the application
   - Use `ps -o user,uid,cmd -C python3` to see the user and numeric uid
   - You can also check `User=` in the unit file

3. On web01 (ops), check the destination's owner and permissions
   - Use `ls -ldn /srv/shared` to inspect numeric uid, gid, and mode rather than names
   - Compare with the uid from step 2 and determine whether that user can write there

4. Once writing is possible, perform an actual upload from web01 (ops) to verify it
   - Run `curl -s -X POST --data-binary @/etc/hostname http://localhost:8080/upload`, then `ls -l /srv/shared`

## Why investigate this area?

If there is no error or log entry but the file is missing, a failure may be getting swallowed somewhere.
Permissions are among the most common causes of save failures.
A username can map to different uids in different environments, so comparing numeric IDs is more reliable.

## Common pitfalls

- Trusting the success response and starting with components outside the application, such as the web server or network
- Looking only at usernames and assuming the ownership matches
- Broadening permissions to 777 because writing fails. Allowing anyone to write creates another problem
