# L008 Only the product list page returns 502

1. On web01 (ops; use sudo for administrative operations), read the nginx error log
   - Use `sudo tail -n 5 /var/log/nginx/error.log` to identify the address it failed to connect to

2. Check which hostname nginx forwards requests to
   - Find the `proxy_pass` destination in the configuration under /etc/nginx/

3. Check which address that hostname resolves to
   - On web01 (ops), run `getent hosts <名前>`
   - Compare it with the address in the error log and check whether it belongs to an internal server

4. Read the file that controls name resolution
   - Use `cat /etc/hosts` and review each manually edited line
   - Check other lines for typos as well as the forwarding destination's entry

5. After correcting it, reload nginx and check both /products and /

## Why investigate this area?

502 Bad Gateway appears when nginx is running but cannot reach its upstream destination.
If the home page works and only /products fails, focus on the upstream for /products.
Recent manual edits to a server configuration file, together with an unfamiliar address in the error log, point to the mapping between names and addresses.

## Common pitfalls

- Assuming the upstream API server is down without reading the address in the error log
- Fixing only the most obvious error and overlooking typos elsewhere in the same file
- Testing without reloading nginx after the correction, leaving the old resolution in use
