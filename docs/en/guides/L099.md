# L099 Nobody knows how to start the system

1. On gw01 (ops; use sudo for administrative operations), find dependencies from the entry-point configuration
   - Read `/etc/gw/gw.conf` to see which host and port it forwards to
   - Use `step-check` to inspect the state of this host's procedure

2. Connect to the discovered host via ssh from toolbox (the left pane), as ops, and follow its dependencies by reading its configuration in the same way (you cannot access other hosts from inside gw01)
   - Find further dependencies in each host's configuration under `/etc`
   - Turn the path traced from the entry point into a table or architecture diagram showing dependency directions

3. On all hosts (ops), check procedure states without making changes
   - Run `step-check` (or `/opt/recover/stepNN --check`) on every host
   - On the DB host, use `recover-status` to check the overall stage
   - Establish an order that satisfies both the dependency directions in the table and each step's prerequisites

4. Execute the procedures from lower-level dependencies toward higher-level dependents on each host (ops, sudo)
   - Ensure execution stops on failure
   - If the application fails to start, check which library version it is trying to load

5. Finally, verify the page from gw01 with `curl -s http://localhost/`

## Why investigate this area?

Without an architecture diagram or runbook, the first job is to build a diagram through observation.
The entry-point configuration specifies what it calls next, so following those references reveals the whole system.
As a rule, bring up the called components (dependencies) before the components that call them (dependents).

## Common pitfalls

- Trying to start hosts in order from the entry point. Higher-level components cannot start while their dependencies are down
- Executing without `step-check` and skipping the required order
- sudo may remove environment variables. Specify required variables explicitly after sudo
