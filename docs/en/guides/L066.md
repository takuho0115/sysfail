# L066 Product prices use an outdated tax rate

1. On app01 (ops; use sudo for administrative operations), check the current price
   - Run `curl -s 'http://127.0.0.1:8080/price?item=A'`

2. Check whether modifying the source and rebuilding is an option
   - Run `bash /srv/src/legacyapp/build.sh` and read why it fails
   - Determine whether the required compiler is available

3. Investigate how the tax rate is stored in the executable
   - Before making changes, back up the original executable as legacyapp.orig using `cp -p`
   - Use `strings -t d /opt/legacyapp/bin/legacyapp` or `grep -abo` to find likely tax-rate values and their offsets
   - Check the bytes at an offset with `xxd -s <位置> -l 8`

4. Plan the modification procedure
   - You cannot write to the executable of a running program (Text file busy). Keep service downtime as short as possible
   - Stopping and starting the service, and writing to the executable, require `sudo`
   - After the modification, start the service and check the price again

## Why investigate this area?

If you cannot build the modified source, the executable you already have is the only available thing to change.
Constants such as tax rates often remain in an executable as strings or numeric values.
Reading the build failure first clarifies why a rebuild is unavailable and helps you decide to look for another approach.

## Common pitfalls

- Modifying the original executable without making a backup. You lose the ability to restore it and cannot meet the completion conditions
- Changing the length of the value being replaced. This shifts surrounding bytes and breaks the program
- Getting stuck on Text file busy without realizing that the program is still running
- Replacing the first matching value without checking its offset when several similar values exist
