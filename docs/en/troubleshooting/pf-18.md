# PF-18 Kernel modules {#pf-18}

Help for item PF-18 of `sysfail doctor`. doctor prints a one-line summary and the URL of this page.

## Modules are not loaded {#missing}

Levels that simulate delay, bandwidth limits and packet manipulation use kernel modules. WSL2 needs no preparation. The game never loads modules itself. Run the two commands doctor shows (one loads now, one keeps them after reboot); the module names depend on your kernel.

If modprobe reports "Module not found" for `nft_meta` or `nft_exthdr`, run it again without those two (some kernels include them in `nf_tables`).

## Cannot be confirmed {#unconfirmed}

When docker runs in another VM or machine, modules cannot be read from this machine. `sysfail doctor --full` starts a check container and checks them on the docker daemon side. If they still cannot be confirmed, run `lsmod` on the machine running the docker daemon.

## Cannot tell whether built in {#builtin}

Without `/lib/modules/$(uname -r)/modules.builtin`, built-in modules cannot be told apart. Built-in modules need no action; check with `grep <module> /lib/modules/$(uname -r)/modules.builtin`.
