# PF-10 Supported environment {#pf-10}

Help for item PF-10 of `sysfail doctor`. doctor prints a one-line summary and the URL of this page.

## Unsupported environment {#unsupported}

Linux + Docker Engine and Docker Engine inside WSL2 are supported. Docker Desktop and other OSes still start the game, but without a guarantee. Free disk space is not monitored during play there, so check docker's disk limit and the host's free space (10GB or more) yourself.

## The environment cannot be identified {#unknown}

The OS or docker kind could not be identified. The game starts but is treated as unsupported.

## Unchecked kernel (WSL2) {#kernel}

On WSL2, kernels not on the checked list still start the game, but they have not been tested. `wsl --update` may move you to a listed kernel.

## macOS (preview) {#macos}

macOS support is in preview and not guaranteed. Checked: the darwin build, unit tests on macOS and install.sh. Not checked: actual play on colima. Levels that route between networks (L052, L068) are stopped before startup on macOS. Please report problems with the macOS issue template on GitHub Issues.

## macOS conditions (P1-P7) {#macos-conditions}

These are what doctor lists as unmet conditions:

- An Apple Silicon (arm64) Mac
- docker points at the colima profile socket (`~/.colima/<profile>/docker.sock`)
- The VM runs as vz/aarch64
- The Mac home or its parents are not mounted (no mounts, or one read-only directory for sysfail)
- The VM is reachable only from the Mac's loopback (default network)
- The VM disk is smaller than the Mac's free space
- The colima, Lima and VM kernel versions are a combination checked on real hardware

## Docker Desktop {#desktop}

Docker Desktop is not supported. For docker versions beyond the reviewed range, the isolation test container is not created on Docker Desktop, so isolation cannot be checked. Use Linux + Docker Engine, or colima on macOS.
