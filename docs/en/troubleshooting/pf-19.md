# PF-19 Game images {#pf-19}

Help for item PF-19 of `sysfail doctor`. doctor prints a one-line summary and the URL of this page.

## Not pulled yet {#missing-fetch}

The official sysfail pulls the images for level environments (el9 and toolbox) from ghcr.io by the digests embedded in the binary. The first play pulls them automatically. Running `sysfail doctor --build` first gets them ready before you play. It is needed only once, downloads about 450MB and uses about 2GB once unpacked.

sysfail uses a pulled image only when its ID and labels match the values embedded in the binary. Another image under the same name is not used; sysfail pulls the right one instead.

## Registry unreachable {#fetch-network}

ghcr.io could not be reached. Check that the machine can reach the internet and resolve the name (`getent hosts ghcr.io`), then run `sysfail doctor --build` again. A machine without internet access can get the images from another machine with `docker save` and `docker load` (README, "Game images cannot be pulled (PF-19)").

## Blocked at the proxy {#fetch-proxy}

The docker daemon pulls the images, so the proxy is set on the daemon, not in `~/.docker/config.json`. On Linux, write `HTTP_PROXY` and `HTTPS_PROXY` (and `NO_PROXY` if needed) in `/etc/systemd/system/docker.service.d/http-proxy.conf`, run `sudo systemctl daemon-reload` and `sudo systemctl restart docker`, then run `sysfail doctor --build` again. On Docker Desktop, use Resources → Proxies in the settings.

## Rate limited {#fetch-ratelimit}

ghcr.io limited the number of requests in a short time (429, toomanyrequests). Wait a while, then run `sysfail doctor --build` again.

## Image not found in the registry {#fetch-notfound}

ghcr.io has no image with the digest this version of sysfail needs. The version may be from before the images were published, or the images were removed. Install the latest version of sysfail, or report it on GitHub Issues.

## Refused by the registry {#fetch-auth}

ghcr.io refused the pull (401, 403). docker may be logged in to ghcr.io with another account that cannot read the images. Run `docker logout ghcr.io`, then run `sysfail doctor --build` again. If it is still refused, report it on GitHub Issues.

## The pulled image is not the expected one {#fetch-mismatch}

The ID or labels of the pulled image did not match the values embedded in the binary, so sysfail removed it without using it. Pulling again would bring the same image, so no manual command is shown. Please report it on GitHub Issues.

## Development build {#nosource}

A sysfail built from source carries no image digests. Pass the repository root with `--assets-dir` to build the images locally (for example `sysfail --assets-dir . doctor --build`).

---

With `--assets-dir` pointing at a directory that has images/, sysfail builds the images locally as before. The sections below are for that case.

## Not built yet {#missing}

The images for level environments are built automatically on the first play. Running `sysfail doctor --build` first finds build problems before you play. It is needed only once and takes 5-20 minutes and about 4GB.

## Packages cannot be fetched {#network}

Packages could not be fetched from the internet during the build. Check the following, then run `sysfail doctor --build` again.

- The machine can reach the internet
- DNS works (`docker run --rm alpine nslookup dl-cdn.alpinelinux.org`)
- Behind a proxy, the docker daemon has `HTTP_PROXY`/`HTTPS_PROXY` set (`/etc/systemd/system/docker.service.d/`)

## Not enough space {#capacity}

The build needs 6GB or more free in docker's data area. Check usage with `docker system df`, remove unused images and containers ([PF-08](pf-08.md#low)), then run `sysfail doctor --build`.

## The build network cannot be created {#netfilter}

docker could not create the build network, usually because kernel modules are missing.

1. Check with `lsmod` that `ip_tables`, `iptable_nat`, `iptable_filter`, `xt_addrtype`, `xt_conntrack`, `br_netfilter` and `veth` are loaded.
2. Load the missing ones (for example `sudo modprobe -a ip_tables iptable_nat iptable_filter xt_addrtype xt_conntrack br_netfilter veth`).
3. Restart docker (`sudo systemctl restart docker`).
4. Run `sysfail doctor --build` again.

With firewalld, also check that the docker zone exists (`sudo firewall-cmd --get-zones`).

## Cannot connect to the docker daemon {#daemon}

The connection to the docker daemon was lost during the build. Check that the daemon is running ([PF-02](pf-02.md#down)), then run `sysfail doctor --build` again.

## Timeout {#timeout}

The build did not finish in time. This happens on slow connections or when docker is busy with other work. Run `sysfail doctor --build` again after other work finishes.

## Other failures {#other}

The last few lines of the docker build output on screen show why it failed. Check them, then run `sysfail doctor --build` again. If it still fails, report it on GitHub Issues with those lines.
