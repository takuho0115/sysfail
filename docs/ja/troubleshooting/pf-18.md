# PF-18 カーネルモジュール {#pf-18}

`sysfail doctor` の PF-18 の項目の説明です。doctor は 1 行の要点とこのページの URL を出します。

## モジュールが読み込まれていない {#missing}

通信の遅延・帯域制限・パケット操作を再現するレベルは、カーネルモジュールを使います。WSL2 では準備は要りません。ゲームはモジュールを自動では読み込みません。doctor が表示する 2 つのコマンド（すぐ読み込むものと、再起動後も残すもの）を実行してください。表示されるモジュール名はカーネルに合わせて変わります。

modprobe が `nft_meta` や `nft_exthdr` について「Module not found」と表示したら、その 2 つを除いて実行し直してください（カーネルによっては `nf_tables` に含まれています）。

## 確認できない {#unconfirmed}

docker が別の VM や別のマシンで動いているときは、この端末からはモジュールを読めません。`sysfail doctor --full` を実行すると、検証用のコンテナを起動して docker デーモンの側で確かめます。それでも確認できないときは、docker デーモンが動いているマシンで `lsmod` を実行して確かめてください。

## 組み込みかどうか判定できない {#builtin}

`/lib/modules/$(uname -r)/modules.builtin` を読めないと、カーネルに組み込み済みかどうか分かりません。組み込み済みなら対処は要りません。`grep <モジュール名> /lib/modules/$(uname -r)/modules.builtin` で確かめられます。
