# PF-19 ゲーム用イメージ {#pf-19}

`sysfail doctor` の PF-19 の項目の説明です。doctor は 1 行の要点とこのページの URL を出します。

## まだビルドしていない {#missing}

レベル環境に使うイメージは、最初の play で自動でビルドします。先に `sysfail doctor --build` でビルドしておくと、ビルドのときに起きる問題を、プレイの前に確かめられます。ビルドは初回だけで、5〜20 分かかり、約 4GB の空きが要ります。

## パッケージを取得できない {#network}

ビルドの途中で、インターネットからパッケージを取得できませんでした。次を確かめてから `sysfail doctor --build` をやり直してください。

- インターネットにつながるか
- DNS で名前解決ができるか（`docker run --rm alpine nslookup dl-cdn.alpinelinux.org`）
- プロキシが要る環境では、docker デーモンにプロキシを設定しているか（`/etc/systemd/system/docker.service.d/` の `HTTP_PROXY`・`HTTPS_PROXY`）

## 空き容量の不足 {#capacity}

ビルドには docker のデータ領域に 6GB 以上の空きが要ります。`docker system df` で使用量を確かめ、使っていないイメージやコンテナを消してから（[PF-08](pf-08.md#low)）、`sysfail doctor --build` を実行してください。

## ビルド用のネットワークを作れない {#netfilter}

docker がビルド用のネットワークを作れませんでした。主な原因は、カーネルモジュールの不足です。

1. 次のモジュールが読み込まれているかを `lsmod` で確かめます: `ip_tables`・`iptable_nat`・`iptable_filter`・`xt_addrtype`・`xt_conntrack`・`br_netfilter`・`veth`
2. 足りないものを読み込みます（例: `sudo modprobe -a ip_tables iptable_nat iptable_filter xt_addrtype xt_conntrack br_netfilter veth`）。
3. docker を再起動します（`sudo systemctl restart docker`）。
4. `sysfail doctor --build` をやり直します。

firewalld を使っている場合は、docker ゾーンがあるかも確かめてください（`sudo firewall-cmd --get-zones`）。

## docker デーモンに接続できない {#daemon}

ビルドの途中で docker デーモンとの接続が切れました。デーモンが動いているかを確かめてから（[PF-02](pf-02.md#down)）、`sysfail doctor --build` をやり直してください。

## 時間切れ {#timeout}

ビルドが時間内に終わりませんでした。回線が遅いときや、docker がほかの作業で混んでいるときに起きます。並行する作業が終わってから `sysfail doctor --build` をやり直してください。

## その他の失敗 {#other}

画面に出ている docker build の出力の最後の数行に、失敗の理由が出ています。それを確かめてから `sysfail doctor --build` をやり直してください。解決しないときは、その数行を添えて GitHub Issues で知らせてください。
