# PF-14 ホスト自身の待ち受け {#pf-14}

`sysfail doctor` の PF-14 の項目の説明です。doctor は 1 行の要点とこのページの URL を出します。

## 全アドレスで待ち受けるポートがある {#exposed}

0.0.0.0・:: やゲームのゲートウェイのアドレスで待ち受けるサービスには、レベル環境のコンテナから通信が届く恐れがあります。サービスの待ち受けを 127.0.0.1 に限るか、下のファイアウォールの例で閉じてください。ゲームは起動します。

## docker の API ポート {#docker-api}

docker デーモンの API（2375・2376）が全アドレスで待ち受けています。`/etc/docker/daemon.json` の `hosts` や、systemd の `-H tcp://...` の指定を外してください。

## ファイアウォールの例 {#firewall}

docker のブリッジ（docker0・br-*）からホストへの通信を拒否する例です。ゲームはこれらの規則を自動では入れません。

- firewalld: `sudo firewall-cmd --permanent --zone=docker --add-rich-rule='rule family=ipv4 reject'` のあと `sudo firewall-cmd --reload`
- nftables: `inet filter input` に `iifname "docker0" reject` と `iifname "br-*" reject`
- iptables: `sudo iptables -A INPUT -i docker0 -j REJECT` と `sudo iptables -A INPUT -i br+ -j REJECT`
- ufw: `sudo ufw deny in on docker0`

WSL2 では、Windows 側ではなく WSL の中の Linux で設定します。
