# PF-15 ブリッジの netfilter {#pf-15}

`sysfail doctor` の PF-15 の項目の説明です。doctor は 1 行の要点とこのページの URL を出します。

## net.bridge.bridge-nf-call-iptables=1 {#enabled}

この設定が 1 だと、docker の internal ネットワークの規則が、ネットワークの間を中継するパケットを捨てます。そのため、中継を使うレベルは起動できません。遊ぶ間だけ 0 にし、終わったら必ず戻してください。

```bash
sudo sysctl -w net.bridge.bridge-nf-call-iptables=0
# 遊び終わったら戻す
sudo sysctl -w net.bridge.bridge-nf-call-iptables=1
```

副作用:

- この設定はホスト全体に効きます。docker の icc=false など、ブリッジの中の分離が効かなくなります。
- WSL2 では、同じ WSL VM の全ディストリビューションに効きます。
- Kubernetes など、1 を前提にするソフトが動いている端末では変えないでください。

## 値を確認できない {#unconfirmed}

docker が別の VM や別のマシンで動いているときは、この端末からは `net.bridge.bridge-nf-call-iptables` の値を読めません。`sysfail doctor` は、検証用のコンテナを起動して、docker デーモンが動いているマシンの値を確かめます。それでも確認できないときは、docker デーモンが動いているマシンで `sysctl net.bridge.bridge-nf-call-iptables` を実行して確かめてください。
