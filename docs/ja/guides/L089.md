# L089 復旧手順の順序が不明確

1. db01（ops、管理操作は sudo）で、現状を変えずに把握する
   - `recover-status` で今の段階と整合性を見る
   - `sudo mariadb` で注文の件数や金額の合計を見て、何が欠けているかをつかむ

2. db01（ops）で、手順書の断片を全部読む
   - `/srv/runbook` の断片を読み、どの手順がどの段階を前提にし、実行後にどの段階になるかを表にする
   - 断片のファイル名の番号は手順の順番ではない

3. db01（ops、sudo）で、全手順を「確認だけ」で試す
   - `/opt/recover/stepNN --check` を 20 個すべてに対して実行する
   - 手順 2 の表と食い違いが無いかを確かめ、順序を確定する

4. 順序が確定してから、db01（ops、sudo）で 1 つずつ実行する
   - 失敗したらそこで止まるように実行し、途中で `recover-status` を見る
   - 最後に段階・件数・合計を確かめる

## なぜそこを疑うか

「順番を誤ると取り返しがつかない」作業では、実行前に状態を変えない確認で手順の前提を集めるのが先です。
断片化した手順書は、並べ方ではなく「前提」と「結果」で並べ替えると順序が決まります。

## つまずきやすい点

- 断片のファイル名の順にそのまま実行すること
- `--check` を一部だけで済ませて、残りを推測で実行すること
- 失敗しても次の手順に進むループで実行すること
- 状態ファイルや DB は root 権限が必要で、`sudo` を付け忘れて失敗の理由を取り違えること
