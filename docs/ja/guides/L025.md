# L025 サイトが 503 エラーになる

1. toolbox（player）でロードバランサーの状態を見る
   - `cloudctl lb describe-target-health --target-group-name web-lb`
   - ターゲットごとの状態と理由（REASON）、ヘルスチェックに使っているパス

2. web01（ops、管理操作は sudo）・web02（ops）で、そのパスに実際に応答するか確かめる
   - `curl -si http://localhost/<ヘルスチェックのパス> | head -1`

3. Web サーバー側でヘルスチェック用に応答しているパスを調べる
   - /etc/nginx/ の設定でヘルスチェック用の location を探す

4. LB と Web サーバーのどちらに合わせるかを決めて直し、`cloudctl lb describe-target-health --target-group-name web-lb` で全ターゲットが healthy になるのを確かめる
   - `cloudctl lb help` で使える操作の一覧が出る（`cloudctl lb <操作> help` で書式を確かめる）

## なぜそこを疑うか

各サーバーのサービスは動いているのに全台が 503 を返すなら、ロードバランサーが振り分け先を 1 台も持っていない可能性が高いです。
LB は自分のヘルスチェックの結果で振り分け先を決めるので、まず LB から見た各台の状態と、その判定に使っている要求を確かめます。

## つまずきやすい点

- 各サーバーで nginx が動いているのを見て「サーバーは正常」と結論すること（LB の判定と食い違う）
- トップページ（/）の応答だけを試して、ヘルスチェックのパスを試さないこと
- Web 側を直す場合に、1 台だけ直してもう 1 台を忘れること
