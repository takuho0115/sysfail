# L075 古い TLS でハンドシェイクが失敗する

1. gw01（ops、管理操作は sudo）で、nginx のエラーログを見る
   - `sudo grep -iE 'handshake|cipher' /var/log/nginx/error.log` で、取引先からの接続がどの段階で失敗しているかを読む
   - 失敗の理由が「共通の暗号が無い」なのか、証明書やプロトコルなのかを見分ける

2. gw01（ops）で、nginx が使う暗号の決め方を確かめる
   - TLS の設定で `ssl_ciphers` が OS のポリシーに従う指定（PROFILE=SYSTEM）になっていないか見る

3. gw01（ops）で、OS の暗号ポリシーの現在値と、いま使える暗号を確かめる
   - `update-crypto-policies --show`
   - `openssl ciphers -v PROFILE=SYSTEM | head`
   - 「強化」の内容が、どの暗号を外したかを読み取る

4. gw01（ops）で、取引先の暗号を再現して試す
   - `sfclient` を引数なしで実行してプロファイルの一覧を見て、古い端末に近いプロファイルで `https://gw01/` に接続してみる（証明書の検証で失敗するときは `--insecure` を付けて、暗号の失敗と切り分ける）

5. 強化を戻さずに、足りない暗号だけを足す方法を探す
   - `/usr/share/crypto-policies/policies/modules/` にあるモジュールを見る
   - 変更後は nginx を再起動し、手順 4 の接続と一般のクライアントの両方で確かめる

## なぜそこを疑うか

「強化のあとから、古い相手だけが失敗する」なら、強化で外れたものを古い相手が必要としていると考えます。
エラーログの「共通の暗号が無い」は、双方が提示した暗号に重なりが無いことを示します。
nginx の設定が OS のポリシーに従う形なら、見るべきは nginx ではなく OS 側です。

## つまずきやすい点

- 相手の暗号を確かめず、推測で暗号を足して終わること。`sfclient` のプロファイルで再現してから直す
- ポリシーを DEFAULT や LEGACY に戻すこと。監査の要件を崩す
- モジュールの指定の仕方（足すのか、置き換えるのか）を確かめずに適用すること
- 適用したあと nginx を再起動し忘れること
