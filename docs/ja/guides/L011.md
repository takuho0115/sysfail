# L011 ECサイトが 1 分足らずで落ちては戻ることを繰り返す

1. web01（ops、管理操作は sudo）で、サービスが再起動を繰り返している様子を確かめる
   - `systemctl status nginx` で、起動してからの経過時間を見る

2. 何がサービスを再起動させているのかをログで探す
   - `journalctl --no-pager | tail -n 30` で、再起動の直前に出ている記録を読む
   - 何回失敗したら再起動するのか、どのくらいの間隔か、という規則性を見る

3. 再起動させている仕組みの設定を探す
   - ログに出た仕組みの名前を手がかりに、`sudo grep -ril <語> /etc` などで設定ファイルを探す
   - 何を、どのコマンドで確認しているのかを読む

4. 監視と同じ確認のコマンドを、手で実行する
   - 成功するか、失敗するなら終了コードは何かを見る
   - `sudo ss -ltnp` で、確認の宛先が実際に待ち受けているかを比べる

5. 確認の宛先と実際のサービスを揃えたら、1 分以上観察して再起動が止まったことを確かめる

## なぜそこを疑うか

サービスが勝手に止まっては戻るとき、サービス自身が落ちているのではなく、外側の監視が「異常」と判断して再起動させている場合があります。
サービスに直接アクセスすると正常なのに再起動されるなら、監視の判断のほうが間違っている、と考えられます。
監視が何をどう確認しているかを読み、手で同じことをすると、食い違いがはっきりします。

## つまずきやすい点

- サービスの起動処理や起動の待ち時間を調整しようとすること（サービス側は正常に動いている）
- 監視の設定を探すのに時間がかかること。ログに出ている名前や語から grep で探す
- ゲームの外（自分の端末）で設定を作ってしまうこと。操作は必ず web01 の中で行う
- 直してすぐ確かめて終えること（再起動の周期をまたいで観察する）
