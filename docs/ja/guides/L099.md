# L099 システムの起動手順が不明

1. gw01（ops、管理操作は sudo）で、入口の設定から依存先を見つける
   - `/etc/gw/gw.conf` を読み、どのホストのどのポートへ中継しているかを見る
   - `step-check` で、このホストの手順の状態を確かめる

2. 見つけたホストへ、toolbox（左のペイン）から ssh で入り（ops。gw01 の中からは他のホストへ入れない）、同じように設定を読んで依存先をたどる
   - 各ホストの `/etc` 配下の設定から、さらに下の依存先を見つける
   - 入口から順にたどった結果を、依存の向きつきの表（構成図）にする

3. 全ホスト（ops）で、変更せずに手順の状態を確かめる
   - `step-check`（または `/opt/recover/stepNN --check`）を全ホストで実行する
   - DB のホストで `recover-status` を見て、全体の段階を確かめる
   - 表の依存の向きと、手順の前提が合うように順序を確定する

4. 依存の下位から上位へ、各ホスト（ops、sudo）で手順を実行する
   - 失敗したらそこで止まるように実行する
   - アプリの起動で失敗したら、どの版のライブラリを読もうとしているかを確かめる

5. 最後に gw01 から `curl -s http://localhost/` で表示を確かめる

## なぜそこを疑うか

構成図も手順書も無いときは、観察で構成図をつくるのが最初の仕事です。
入口の設定は「次にどこを呼ぶか」を必ず持っているので、そこからたどれば全体が見えます。
起動は、呼ばれる側（下位）から呼ぶ側（上位）の順にそろえるのが基本です。

## つまずきやすい点

- 入口のホストから順に起動しようとすること。依存先が動いていないと上位は起動できない
- `step-check` をせずに実行して、順序を飛ばしてしまうこと
- sudo で実行すると環境変数が消えることがある。必要な変数は sudo の後ろで明示する
