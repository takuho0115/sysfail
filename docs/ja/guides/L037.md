# L037 古い端末からだけ HTTPS 接続に失敗する

1. toolbox（player）で、古い端末と最新のブラウザの接続を比べる
   - `sfclient --help` で使えるプロファイルを確かめる
   - `sfclient --profile legacy --insecure https://web01/` と `--profile modern` の結果とエラーの文面を比べる

2. web01（ops、管理操作は sudo）で nginx の TLS の設定を読む
   - /etc/nginx/conf.d/tls.conf の ssl_protocols と ssl_ciphers

3. web01（ops）で、古い端末が使う暗号スイートを指定して接続を試す
   - `openssl s_client -connect localhost:443 -tls1_2 -cipher <暗号スイート名> </dev/null`
   - 失敗の理由が、プロトコルなのか暗号スイートなのかを見分ける

4. 設定を直したら `sudo nginx -t` のあと再読み込みし、toolbox で legacy と modern の両方を試す

## なぜそこを疑うか

最新のブラウザは通るのに古い端末だけ失敗するなら、サーバーは動いていて、端末とサーバーが TLS の条件で合意できていません。
ハンドシェイクの失敗はプロトコルのバージョンか暗号スイートのどちらかが共通でないときに起きるので、サーバーが許可している一覧と、古い端末が使えるものを突き合わせます。

## つまずきやすい点

- 古い端末のために TLS 1.0・1.1 を有効にすること（完了条件で禁止されている）
- 似た名前の暗号スイート（鍵交換の方式だけが違うもの）を足して、通ったつもりになること。legacy プロファイルそのもので確かめる
- 暗号スイートを大量に足して、安全性を必要以上に下げること
