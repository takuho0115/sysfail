# L019 画面は出るが商品一覧が読み込まれない（ブラウザのエラー）

1. toolbox（player）で画面の動作を再現する
   - `browser-sim http://shop.acme.internal/` でエラーの文面を読む

2. toolbox（player）で、ブラウザと同じ条件の要求を curl で送る
   - `curl -si -H 'Origin: http://shop.acme.internal' http://api.acme.internal:8080/products`
   - 本文ではなく応答ヘッダーを見る。許可を示すヘッダーが付いているか
   - OPTIONS の要求（プリフライト）への応答も確かめる

3. api01（ops、管理操作は sudo）で nginx の設定を読む
   - /etc/nginx/conf.d/ の API 用の設定に、許可するオリジンの指定があるか

4. 設定を直したら `sudo nginx -t` で検査してから reload し、toolbox で `browser-sim` を再確認する

## なぜそこを疑うか

curl では 200 が返るのにブラウザでだけ失敗するなら、API 自体は動いていて、ブラウザが応答を捨てています。
ブラウザは別オリジンへの要求では、サーバーが許可を示すヘッダーを返しているかを確かめます。そのため curl でも Origin を付け、本文ではなくヘッダーを見ます。

## つまずきやすい点

- curl が成功したので API に問題はないと判断して止まること
- Origin を付けずに curl して、ブラウザとの違いを再現できないこと
- GET だけ直してプリフライト（OPTIONS）を忘れること
- 許可を `*` で全開放すること（完了条件で禁止されている）
- reload の直後に古いワーカーが前の設定で応答したのを見て、直っていないと判断すること（少し待って再確認する）
