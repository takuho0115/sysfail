# L041 注文の処理が滞留する

1. gw01（ops、管理操作は sudo）で、接続が溜まっている様子を確認する
   - `ss -s` や `sudo ss -tnp` で、確立済みの接続がどこに向かって何本あるかを見る
   - `curl -s -m 3 -w '%{http_code}\n' http://gw01:8080/order` で、待たされるのか失敗するのかを確かめる

2. 各サービスのログを読む
   - gw01・svc-a・svc-b・svc-c（いずれも ops）で `journalctl -u mesh-svc --no-pager | tail -n 20` を実行する
   - 同じリクエスト ID（req=...）が何度も出てこないか注目する

3. 呼び出しの向きを表にする
   - 各サーバーの /etc/mesh/svc.conf の upstream を `grep -H '^upstream' /etc/mesh/svc.conf` で集める
   - 「どこから、どこへ」を 1 行ずつ書き出し、gw01 から順にたどって終点があるかを確かめる

4. 原因の設定を直したあと、溜まった接続を解放する
   - 設定を戻すだけでは、すでに詰まっているワーカーは空かない。各サービスを再起動する
   - svc-a（ops）で `ss -tn state established | wc -l` を見て、接続数が下がったことを確認する

## なぜそこを疑うか

どのサービスも遅く、接続数も全台で高止まりしているときは、1 台の不調よりも、サービスどうしのつながり方の問題を疑います。
同じ要求がログに何度も現れるのは、要求が終わらずにサービスの間を回り続けている印です。
設定を表にして呼び出しの向きをたどれば、どこで流れが戻っているかが分かります。

## つまずきやすい点

- 一番遅く見えるサービスだけを再起動して様子を見ること。原因が残っていれば、すぐまた埋まります
- 各サービスの設定を頭の中でつなげようとして、向きを取り違えること。紙やメモに表として書き出すと確実です
- 設定を直したあと再起動せず、詰まったワーカーが残ったまま待ち続けること
- 別のサービスのホストへは、gw01 の中からではなく、toolbox（左のペイン）から ssh で入ること（ホストの中には他のホストへ入る鍵が無い）
