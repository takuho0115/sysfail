# L087 デーモンが起動して終了する

1. mw01（ops、管理操作は sudo）で、サービスの状態と終了のしかたを確かめる
   - `systemctl status vendord` で、異常終了なのか正常終了（終了コード 0）なのかを見る
   - ユニットファイルで、出力が捨てられる設定になっていないかも見る

2. mw01（ops）で、手で起動して終了コードを見る
   - `/opt/vendor/vendord; echo "exit=$?"`

3. mw01（ops、sudo）で、外から挙動を観察する
   - `strace -f -e trace=network,openat /opt/vendor/vendord`
   - どのホストの何番ポートに接続しようとしたか、失敗したあとにどのファイルを開いたかを読む

4. mw01（ops）で、接続先が本当に使えないのかを確かめる
   - `ss`、`nc` などで、そのホスト・ポートが応答するかを見る
   - 接続先を直せないなら、手順 3 で開いていたファイルと、それを扱う付属のツールを調べる

5. mw01（ops）で、社内に残る手順書を探して読む
   - `/srv/runbook` の中から、接続先が使えないときの運用を探す
   - 書かれている公式の手順だけを使って直し、vendord を起動して 7000 番ポートと app01 の状態表示を確かめる

## なぜそこを疑うか

何も出さずに終了コード 0 で終わるプログラムは、「動く条件がそろっていない」と自分で判断して終わっていることが多いです。
ログが無いときは、システムコールを外から見ると、何を確かめに行って何に失敗したかが分かります。
これは中身の解析ではなく挙動の観察なので、契約の制約にも触れません。

## つまずきやすい点

- ログが無いことで手詰まりと考えてしまうこと。strace で外から観察できる
- 接続先の失敗だけを見て、その直後に開いているファイルを見落とすこと
- 本体のバイナリを書き換えたり、手順書に無い方法で回避したりすること
