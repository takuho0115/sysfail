# L002 外部からショップに接続するとタイムアウトする

1. web01（ops、管理操作は sudo）で、サービス自体が動いているかを確かめる
   - `ss -ltn` で 80・443 を待ち受けているか
   - `curl -I http://localhost/` と `curl -k -I https://localhost/` で、サーバーの中からは応答が返るか

2. toolbox（player）から web01 へのアクセスを試し、失敗の仕方を見る
   - `curl -I http://web01/` が「接続拒否」ですぐ返るのか、「タイムアウト」で待たされるのか

3. サーバーの手前にある仕組みを調べる
   - toolbox（player）で `cloud sg describe-security-groups` を実行し、web01 に関係するセキュリティグループを探す
   - `cloud sg describe-security-groups --group-ids <名前>` で受信ルールを読み、どのポートが、どの送信元から許可されているかを表にする

4. 足りない許可を、必要な範囲だけ加える
   - 追加の方法は `cloud sg help` で出る操作の一覧から探し、`cloud sg <操作> help` で書式を確かめる
   - 送信元は、既存のルールでどの範囲に絞られているかを参考に決める

5. toolbox（player）から web01 へのアクセスをもう一度確かめる

## なぜそこを疑うか

サーバーの中では表示できて外からは届かないなら、サービスではなく「サーバーまでの道」に問題があります。
タイムアウトになるのは、通信が途中で黙って捨てられているときの典型です。
接続拒否なら相手が待ち受けていない、タイムアウトなら手前で止められている、と読み分けると調べる場所を絞れます。

## つまずきやすい点

- サーバー内の nginx の設定ばかり見直してしまうこと（中から表示できるなら、そこは問題ではない）
- 許可を追加するときに、送信元を全開放（0.0.0.0/0）にしてしまうこと（既存のルールの範囲に揃える）
- 既存の SSH のルールを広げたり消したりしてしまうこと
