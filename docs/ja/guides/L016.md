# L016 注文を確定すると応答が返ってこない

1. 症状の範囲を確かめる
   - 閲覧はできて、注文の確定だけが返らない。DB の CPU 使用率は低い

2. db01（ops、管理操作は sudo）で、DB のセッションの状況を見る
   - `sudo mysql -e 'SHOW FULL PROCESSLIST'` で、何が動いていて何が待たされているかを一覧にする

3. 待たされている側と、待たせている側を分ける
   - 待たされているセッションの `State` を読み、何を待っているかを確かめる
   - 同じテーブルを使っていて実行時間（`Time`）が長いセッションを探す

4. 待たせている側が何のためのクエリかを確かめる
   - ユーザー名やクエリの内容から、止めてよいものかを判断する

5. 止めると決めたセッションだけを終了させ、注文の確定を確かめる
   - 注文データそのものには手を付けない

## なぜそこを疑うか

応答が返らないのに CPU 使用率が低いなら、処理が重いのではなく「何かを待っている」状態です。
DB では、ほかのセッションがテーブルを使い続けていると、後から来た処理はロックの解放を待つことになります。
どのセッションがどのセッションを待たせているかは、セッションの一覧の状態と実行時間を並べると見えてきます。

## つまずきやすい点

- 待たされている側（注文の処理）を止めてしまうこと。待たせている側を探す
- 中身を確かめずに長いクエリを片端から終了させること。何のためのクエリかを先に見る
- 注文データを消したり、テーブルを作り直したりして済ませること
