# L067 プロセスが不定期に落ちる

1. img01（ops、管理操作は sudo）で、落ち方を確かめる
   - `systemctl status imgsvc` と `journalctl -u imgsvc --no-pager` で、終了の理由（status= やシグナル名）と間隔を読む
   - プロセスが自分で終了したのか、シグナルで落ちたのかを見分ける

2. 落ちたときの記録を集める
   - `ls /var/lib/sfcore` で、クラッシュのたびに残る擬似コアを確かめる
   - 複数のコアのバックトレースを並べて読む

3. 毎回違う場所と、毎回共通する場所を分ける
   - 落ちた関数そのものではなく、どのコアにも出てくる関数に注目する

4. その共通点に関わる設定を探す
   - /etc/imgsvc/env など、サービスの設定を見て、共通点に結びつく項目を探す
   - 変えたあとは再起動し、しばらく落ちないことを確かめる（完了条件は 1 分以上の継続を見ています）

## なぜそこを疑うか

落ちる場所が毎回違うのは、どこかで壊れたメモリを、後から別の処理が踏んでいる典型です。
1 回分のバックトレースだけを見ると、たまたまそこで動いていた処理を原因と取り違えます。
何回分かを読み比べ、場所が変わっても必ず通っている処理を探すと、原因に近づけます。

## つまずきやすい点

- 最新の 1 回のコアだけを読んで、そこに出た関数を直そうとすること
- 自動で復帰するので、落ちていないように見えて見逃すこと。ログの再起動の記録を確かめてください
- 設定を変えたあとすぐに判断すること。数十秒おきに落ちるので、数分は様子を見る必要があります
